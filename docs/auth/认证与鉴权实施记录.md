# 认证与鉴权生产可用实施记录

> 日期：2026-09-16
> 实施范围：后端 + 前端最小登录态，CLI 可用

---

## 1. 本次实现了什么

### 1.1 可插拔认证层

新增 `interfaces/web/auth.py`，提供三种模式，默认 `disabled`，不影响现有本地单用户体验：

| 模式 | 用途 | 当前状态 |
| --- | --- | --- |
| `disabled` | 保持原有行为 | ✅ 完整实现 |
| `apikey` | CLI / M2M 快速保护 | ✅ 完整实现 + 数据库存储 + 管理端点 |
| `oidc` | 对接 Authentik 等自托管 IdP | ✅ 后端流程完整（登录、回调、JWKS 验签、会话 Cookie） |

### 1.2 主体与权限模型

- 新增 `application/principal.py`：
  - `Principal` 不可变对象
  - 角色：`admin` / `member` / `viewer`
  - 权限新增：`apikey:manage`、`audit:read`
- 新增 `application/errors.py` 异常：`NotFoundError`、`OwnershipError`、`PermissionDeniedError`

### 1.3 数据归属

- `thread_meta` 表新增 `owner_id TEXT NOT NULL DEFAULT ''`
- `ThreadService` / `RunService` 所有方法均接受 `Principal`，并做所有权校验
- 默认关闭（`auth_mode=disabled`）时 owner_id 为空，行为完全向后兼容
- 开启认证后，用户只能看到/操作自己的会话；`admin` 可访问全部
- 首条消息时自动认领会话（解决「ID 先分配、元数据后写入」的设计）

### 1.4 API Key 管理（生产级）

- 新增 `runtime/api_key_store.py`
- 数据库表 `api_keys` 存储：key_id、SHA-256 哈希、前缀、role、scopes、启用状态、过期时间、吊销时间
- 明文 key 只在创建时返回一次
- 校验使用 `secrets.compare_digest` 防止时序攻击
- 保留 `AUTH_API_KEY_DEV` 作为最小可用快速入口；生产环境建议置空并走数据库存储

管理端点（需 `apikey:manage` 权限，admin 默认拥有）：

- `POST /auth/api-keys` — 创建 key
- `GET /auth/api-keys` — 列出 key
- `DELETE /auth/api-keys/{key_id}` — 吊销 key

### 1.5 OIDC Device Flow（CLI 登录）

- 新增 `runtime/device_flow_store.py`
- 流程：
  1. CLI 调用 `POST /auth/device/authorize` 获得 `user_code`
  2. 用户打开浏览器访问 `/auth/device/activate?user_code=XXX` 并登录
  3. 用户点击「批准」，后端创建带过期时间的 API Key
  4. CLI 轮询 `POST /auth/device/token`，拿到 `access_token`（即 API Key）
- 支持自动打开浏览器
- 配置项：`DEVICE_FLOW_EXPIRES_IN_SECONDS`、`DEVICE_FLOW_POLL_INTERVAL_SECONDS`、
  `DEVICE_FLOW_API_KEY_EXPIRES_IN_DAYS`、`OIDC_DEVICE_FLOW_BASE_URL`

新增端点：

- `POST /auth/device/authorize`
- `GET /auth/device/activate`
- `POST /auth/device/activate`
- `POST /auth/device/token`

### 1.6 审计日志

- 新增 `runtime/audit_store.py`
- 记录事件：
  - `thread_delete`
  - `thread_run`
  - `hitl_decision`
  - `login_success`
  - `login_failure`
  - `logout`
  - `apikey_auth_success`
  - `apikey_auth_failure`
  - `apikey_created`
  - `apikey_revoked`
  - `permission_denied`
  - `device_flow_initiated`
  - `device_flow_approved`
  - `device_flow_completed`
- 字段：`event_type`、`actor_id`、`target_id`、`action`、`outcome`、`ip`、`user_agent`、`details`、`created_at`
- 新增 `GET /auth/audit` 端点（需 `audit:read`）

### 1.7 认证端点限流

- 新增 `application/rate_limiter.py`
- 内存级滑动窗口限流，按客户端 IP 计数
- 保护 `/auth/login`、`/auth/callback`、API Key 校验、device flow 端点
- 配置项：`AUTH_RATE_LIMIT_WINDOW_SECONDS`、`AUTH_RATE_LIMIT_MAX_ATTEMPTS`

### 1.8 受保护的 API

以下端点已接入认证与鉴权：

- `POST /api/threads` → `thread:create`
- `GET /api/threads` → `thread:list`
- `GET /api/threads/{id}` → `thread:read`
- `DELETE /api/threads/{id}` → `thread:delete`
- `POST /api/threads/{id}/runs` → `thread:create`
- `POST /api/threads/{id}/resume` → `thread:create`
- `GET /api/models` → 公开

新增认证端点：

- `GET /auth/config` — 返回认证模式、登录/退出/me URL
- `GET /auth/login`（仅 OIDC）
- `GET /auth/callback`（仅 OIDC）
- `GET /auth/logout`
- `GET /auth/me`
- `POST /auth/device/authorize`
- `GET /auth/device/activate`
- `POST /auth/device/activate`
- `POST /auth/device/token`

### 1.9 前端登录态

- `index.html` 顶部增加 `#auth-status`
- `app.js`：
  - 启动时读取 `/auth/config`
  - 未登录时显示「登录」链接
  - 已登录时显示用户名 + 「退出」链接
  - 所有 API 调用 401 时自动跳转登录页（OIDC 模式）

### 1.10 前端管理面板

- 管理员顶部出现「管理」入口
- 管理面板包含两个页签：
  - **API Keys**：创建（带角色/作用域/描述/过期时间）、列出、吊销
  - **审计日志**：表格展示最近 100 条记录
- 创建 API Key 后弹出复制弹窗，提示「明文 key 只显示一次」

### 1.11 CLI 适配

- CLI 可直接读取 `HARNESS_API_KEY` 环境变量，在 `apikey` 模式下认证
- 优先校验 `AUTH_API_KEY_DEV`，其次走数据库 key store
- `disabled` 模式下 CLI 行为不变
- `oidc` 模式下 CLI 通过 OIDC Device Flow 完成无浏览器登录，自动获取 API Key

### 1.12 历史会话迁移

- 新增 `scripts/migrate_thread_owners.py`
- 把 `thread_meta.owner_id = ''` 的会话批量归属到指定用户
- 用法：
  ```bash
  python scripts/migrate_thread_owners.py \
    --db-path ./.data/agent.db \
    --owner-id admin@example.com \
    --dry-run
  ```

## 3. 如何启用

### 3.1 默认（不启用）

```bash
cp .env.example .env
python main.py web
```

行为与之前完全一致，无需额外配置。

### 3.2 API Key 模式（CLI 可用）

```env
AUTH_MODE=apikey
AUTH_SESSION_SECRET=your_32_byte_secret
AUTH_API_KEY_DEV=your-dev-key
```

CLI：

```bash
set HARNESS_API_KEY=your-dev-key
python main.py cli
```

Web 前端不会自动带 API Key，因此 `apikey` 模式目前主要面向 CLI / M2M。

### 3.3 OIDC 模式（Authentik）

```env
AUTH_MODE=oidc
AUTH_SESSION_SECRET=your_32_byte_secret
AUTH_COOKIE_SECURE=true
AUTH_COOKIE_SAMESITE=lax
OIDC_ISSUER=https://auth.example.com/application/o/myagentharness/
OIDC_CLIENT_ID=myagentharness
OIDC_CLIENT_SECRET=your_client_secret
OIDC_REDIRECT_URI=https://harness.example.com/auth/callback
```

然后访问 Web，未登录时会自动显示「登录」链接。

CLI 在 OIDC 模式下使用：

```bash
# 先启动 Web 服务
python main.py web

# 在另一个终端运行 CLI，会提示浏览器授权
python main.py cli
```

### 3.4 API Key 管理

管理员登录后，点击顶部「管理」→「API Keys」：

- 创建 key（选择角色、作用域、过期时间）
- 创建成功后弹窗显示明文 key，请立即复制保存
- 可随时吊销不再使用的 key

### 3.5 审计日志

管理员登录后，点击顶部「管理」→「审计日志」，可查看最近 100 条认证与操作记录。

### 3.4 历史数据迁移

开启认证前，先把旧会话归属到管理员：

```bash
python scripts/migrate_thread_owners.py \
  --db-path ./.data/agent.db \
  --owner-id admin@example.com
```

## 4. 生产 checklist

- [ ] `AUTH_MODE` 设为 `apikey` 或 `oidc`
- [ ] `AUTH_SESSION_SECRET` 至少 32 字节，且与任何其他密钥不同
- [ ] `AUTH_COOKIE_SECURE=true`（必须配合 HTTPS / 反向代理）
- [ ] `AUTH_COOKIE_SAMESITE=lax`（OIDC 回调需要）或 `strict`
- [ ] 生产环境把 `AUTH_API_KEY_DEV` 置空，使用「管理」面板创建可轮换 key
- [ ] CLI 走 OIDC 时，确认 `OIDC_DEVICE_FLOW_BASE_URL` 指向正确的 Web 服务地址
- [ ] 开启认证前执行 `scripts/migrate_thread_owners.py`
- [ ] 在网关层做更严格的全局限流
- [ ] 定期备份 SQLite（thread_meta、audit_log、api_keys、device_flows 都在同库）

## 5. 已知限制

1. **API Key 哈希强度**：当前使用 SHA-256；高安全场景建议迁移到 bcrypt/Argon2。
2. **限流是内存级**：多实例部署时需要在网关/Redis 层统一限流。
3. **审计未记录业务 IP/UA**：thread_run/hitl/thread_delete 的审计只含 actor 与 outcome，不含 IP；
   认证事件已完整记录 IP/UA。
4. **HITL 审批权限**：当前 resume 只要 `thread:create`，未单独拆分 `hitl:approve`。
