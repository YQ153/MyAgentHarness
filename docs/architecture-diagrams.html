MyAgentHarness 架构图（源码实测版）

本页由应用源码逐文件反向生成的**独立**架构图集，不修改也不追加 docs/overview/architecture.html。 图中每个节点都标注了真实文件路径与符号名，可逐条回源码核对。全部图形用原生 HTML/CSS 绘制，无外部依赖，可离线打开。

一句话架构 一套内核 + 两个适配器 + 六个受约束的包。 main.py 分发 CLI / Web 两种形态，两者共用同一条装配流水线 （bootstrap/core.py::build_app_context）；Agent 内核只经 agent/graph.py::build_agent 的单一入口装配 deepagents.create_deep_agent；层间依赖方向由 .importlinter 与 3 个契约测试强制，而非靠文档约定。

图 5运行编排内部协作

RunService 是接口层唯一认识的运行入口，但它本身很薄——真正的状态与规则被拆给三个协作者，构造期一次性装配。

组合结构 
RunService(config, thread_store, graph_factory,
           workspaces, audit_store, usage_store, tool_catalog)
 ├── self._registry = RunRegistry(config)
 │      槽位 / 累计计数 / 限流 / HITL 挂起登记
 ├── self._governor = RunGovernor(config, registry, audit=self._audit)
 │      超时取消 · 审批过期（同一把 Lock，临界区不 await）
 └── self._branches = RunBranchService(
           config, thread_store, graph_factory,
           registry, workspaces, audit=self._audit)
        编辑/重生分叉：只准备，不产出事件
职责边界（谁不做什么）
  • RunRegistry：不碰图、不产出事件，只维护运行态事实
  • RunGovernor：只读 registry 快照 + abort_scope，不做业务判断
  • RunBranchService：返回 ForkPlan，事件由 RunService._consume 统一产出
  • ThreadService：会话聚合读写，与运行期事件流解耦
  • SessionRegistry：解析根 + 装配服务，不承载运行语义
