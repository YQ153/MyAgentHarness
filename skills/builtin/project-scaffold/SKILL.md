# 生成项目骨架

## 何时使用

- 用户要求从零建一个项目或模块的骨架
- 用户要求按某个约定补齐目录结构

## 流程

1. **先确认三件事**：语言与框架、项目名、要不要测试与格式化配置。缺哪一项就问，不要猜
   ——猜错方向意味着整个骨架要重来。
2. 用 `write_todos` 列出要落盘的文件清单，每个文件附一句用途。清单先给用户看一眼再开工，
   这比写完再改便宜得多。
3. 逐个用 `write_file` 落盘。内容写**最小可用版本**：能跑起来的一小段，胜过一堆
   `TODO` 占位——占位版看起来完成了，实际什么都不能跑。
4. 用 `ls` / `glob` 复核：清单里的每个文件都确实存在。漏一个的表现是用户后面在某一步
   报错，而那时已经离现场很远了。
5. 回报时给出三样：目录树、每个文件的用途、**用户需要自己执行的后续命令**（安装依赖、
   运行测试等）。

## 边界

- **不执行** `npm install` / `pip install` 之类的命令：本环境没有终端工具，只能由用户
  在本地执行。不要假装执行过。
- 不生成二进制文件；确实需要二进制资源时，说明由用户补充。
