# 整理成 Markdown

## 何时使用

- 用户要求把若干份资料汇总成一份文档
- 用户要求把散落的内容整理成有层级的说明

## 流程

1. 用 `ls` / `glob` 列出候选文件，**先和用户确认范围**：哪些要进来、哪些不要。范围猜错
   会让后面所有工作白做。
2. 读源文件。不同来源信息冲突时，**保留冲突并标注各自出处**，不要随手挑一个——挑错的那
   个你无从判断，而用户一眼能看出来。
3. 产出结构：
   - 一级标题 = 文档主题
   - 每个来源一节，节内保留源文件的层级
   - 末尾一节「来源」，列出用到的文件路径
4. 用 `write_file` 落盘到工作区。文件名与用户确认的语义一致（例如 `docs/overview.md`），
   不要起 `output.md` 这类无从辨认的名字。
5. **重新 `read_file` 读一遍产出**，确认格式与内容都对，再回报。写完不检查等于把校验
   推给用户。

## 边界

- 不修改原文档；产出是新文件。
- 不做翻译或改写，除非用户明确要求。
- 信息不足时留「待补充」并指明缺什么，不要编。
