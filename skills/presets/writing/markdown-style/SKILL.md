# Markdown 写作规范

## 何时使用

- 撰写或修改 README、设计文档、说明文档；
- 用户要求「统一格式」「润色文档」「整理一下这份文档」。

## 规范

1. **标题**：层级不跳级（`#` → `##` → `###`）；同层标题超过 6 个时，考虑拆成多份文档；
2. **中英混排**：中文与英文/数字之间留一个空格（`使用 Python 3.14`）；中文标点前后不留空格；
3. **代码**：行内代码只用于**标识符与命令**（`SessionRoot`、`pytest -q`）；块级代码必须标语言（```python），不留空语言；
4. **列表**：同一列表内项目符号一致；条目为完整句子时以句号结尾，短语不加；
5. **表格**：列数对齐、表头明确；超过 5 列时改用分节列表；
6. **链接**：指向仓库内文件用相对路径，绝对链接只用于外部资源；
7. **删空话**：去掉「众所周知」「非常简单」这类不含信息的句子。

## 步骤

1. 通读全文，**先修结构**（标题层级、段落顺序），再修细节（空格、标点、代码标注）；
2. 逐条核对上面的规范，记录改动了哪些**类别**（而不是逐字 diff）；
3. 交付时给出「改了几类问题 + 仍存疑之处」，存疑处不要静默改成另一种写法。
